# AGENTS.md

This file provides guidance to any coding agent working in this repository. It carries rules, decisions, and constraints; behavior documentation lives in README.md, and the structural contract lives in spec.md.

## Project

lattice-music is a CLI/TUI toolkit for music libraries that treats the filesystem as the source of truth. It reads tags through `mutagen`, walks the tree on every invocation (no index/database), and writes plain `.txt` reports. Since 5.0.0 it has carried opt-in write modes promoted from the companion scripts (`--clean`, `--apestrip`: dry-run by default, `--apply` to write, always logged); since 5.7.0 a third, `--lyrics` (LRCLIB → same-basename `.lrc` sidecars, same discipline, and the package's one network touchpoint); since 6.0.0 also `--replayGain` (the rsgain-driven ReplayGain 2.0 writer), `--retag` (the genre rewriter, dir-scoped), the `--genreTidy-build`/`--genreTidy-apply` authority pair, and `--genreMap` (the folder-moving restructurer; the scripts by those names are now launchers); since 6.4.0 also `--stripRatings` (the rating-tag stripper: deletes nonzero rating tags only, through the same rating-source helpers `tags.py` decodes with, and the first stage of `--ingest`). Python 3.14+, packaged with Hatch (`pyproject.toml`). Runtime deps: `mutagen`, `tqdm`, `vir-tui` (TUI primitives; PyPI floor `>=2.5.0`). The current version is kept in `src/lattice/config.py` and mirrored in `pyproject.toml` (must stay in sync).

The global rules file at `~/.zcode/AGENTS.md` covers the cross-project rules (git habits including the release/tag procedure, code style, prose style, tooling). This file overrides it for work scoped to lattice-music.

**CLI surface contract:** lattice is a reference implementation of the workspace CLI machine-surface contract (`~/.gitrepos/CLAUDE.md`, Throughlines): machine help carries exit codes, integrity tiers, and per-mode examples (`help --json`), errors are one clean line on stderr (never a traceback), and surfaces are additive-only. The 2026-11-13 follow-up closed in v6.4.2: a missing library root takes the exit-2 usage class on stderr (one line naming the path), and an existing-but-empty root keeps the true empty report on exit 0.

## Common commands

```bash
# Run from a checkout (without installing)
python -m lattice [flags]              # entrypoint: src/lattice/__main__.py

# Install editable into the active venv (uv-friendly)
pip install -e .

# Install as a user-global CLI
pipx install .                         # exposes `lattice`

# Standalone binary (PyInstaller, declared in pyproject.toml)
hatch run build-bin                    # → dist/lattice

# Launch interactive TUI (no args)
lattice

# Most-used modes
lattice --library --output library.txt --genres
lattice --testFLAC --workers 4
lattice --extractArt --dry-run
lattice --stats

# Write modes (dry-run by default; --apply writes, always logged)
lattice --clean ~/Music --apply
lattice --apestrip ~/Music --apply --keep-metadata
lattice --replayGain ~/Music --apply --skip-tagged
```

`just` recipes: `just test` (pytest over the tree), `just lint`, `just fmt`, `just version`, and `just help-doc` (regenerate `docs/help.md` from the live parser).

Tests live in top-level `tests/` (stdlib `unittest`, no third-party deps); run them from the repo root with `python -m unittest discover` (838 tests as of the 2026-11-24 docs pass; pytest also works). The cli/tui kwargs-parity pins live in `test_tui.py` (both faces must build the same kwargs and call the same `modes/*` functions; the c6575dc migration regressions shipped because nothing did). They cover the pure helpers (rating/key normalization, duration clustering, JPEG/PNG header parsing, filename cleanup, track-number parsing, decode classification) and the mode functions end to end against a committed fixture library (`tests/fixtures/library/`, regenerated by `tests/fixtures/build.py` with ffmpeg + mutagen). The `scripts/` companions are tested too (`test_retag.py`, `test_cleaner.py`, `test_genre_tidy.py`, `test_rerate.py`, `test_genre_foldermap.py`, `test_replaygain.py`, `test_apestrip.py`): pure helpers directly, mutating paths against tempfile trees / fixture copies. `test_cleaner.py` and `test_apestrip.py` exercise the package modules behind those two scripts (`lattice.norm`, `lattice.modes.clean`, `lattice.modes.apestrip`); `test_write_modes.py` pins the CLI/TUI wiring of the write modes; `test_help_doc.py` pins `docs/help.md` to the live help index. Subprocess engines (flac/ffmpeg in the integrity modes, rsgain in `--verifyReplayGain`) are never invoked by the suite; their command builders and parsers are unit-tested instead. When changing a covered helper or mode, update its test in the same pass.

System tools used by integrity modes: `flac` (preferred for `--testFLAC`) and `ffmpeg` (everything else, plus FLAC fallback). Both should already be on Fedora via `dnf`.

## Architecture

Layer-based package under `src/lattice/`:

```
cli.py     argparse + dispatch: every mode flag maps to one function call
tui.py     curses full-screen menu shown when invoked with no args
help.py    the two-level help surface: the categorized --help mode index and
           the per-mode `lattice help MODE` pages, all rendered from one
           registry; cli.py intercepts the help paths before argparse
tags.py    get_all_tags() → TagBundle, single MutagenFile() open per file
norm.py    pure name/tag normalization rules (the fold tables, normalize_name,
           canonical_render, tag_fold, tag_dedupe, canon_track_artist); zero I/O
config.py  VERSION, DEFAULT_*_OUTPUT names, AUDIO_EXTENSIONS, COVER_NAMES,
           the tag-read worker count (DEFAULT_TAG_WORKERS/get_tag_workers),
           and persistent library root in ~/.config/lattice/config.json
utils.py   filesystem walk, progress bar factory (_make_pbar), subprocess
           helper, layout parser, terminal reset
modes/     one file per mode group: library, integrity, artwork, audit,
           stats, playlists, lyrics, clean (the --clean write mode: Run
           virtual filesystem + the four consolidation/normalization passes),
           apestrip (the --apestrip write mode), replaygain (the
           --replayGain write mode: the rsgain driver), retag (the --retag
           write mode: the package's one genre-write path, plus the
           --strip-junk junk-frame strip), genretidy (the --genreTidy-build /
           --genreTidy-apply authority pair), foldermap (the --genreMap
           folder-moving write mode), stripratings (the --stripRatings
           write mode: deletes nonzero rating tags via tags.py's shared
           rating-source predicates), ingest (the --ingest ritual: it
           sequences the package modes, never re-implements them). The
           shared dry-run virtual filesystem both moving modes plan against
           lives in lattice/vfs.py.
           Each exports run_* / write_* functions.
```

Both `cli.py` and `tui.py` call into `modes/*` directly. The TUI is not a wrapper around the CLI parser; it builds the same kwargs and invokes the same mode functions. Keep them in sync when adding a flag: argparse entry in `cli.py`, dispatch branch in `cli.py:main`, and a corresponding TUI menu entry in `tui.py`.

`tags.py` is the only place that knows about per-format tag layouts (ID3 frames, Vorbis comments, MP4 atoms, ASF). All other code consumes a `TagBundle`. Ratings are normalized to a 0-5 float in `utils.normalize_rating`; format-specific rating sources (POPM, TXXX, Vorbis `RATING/SCORE/STARS`, MP4 `*rate*`) are decoded inside `get_all_tags`.

Mode functions accept `root`, `output`, `quiet`, and (where relevant) `workers`, `verbose`, `dry_run`, `layout`. Output paths default to constants in `config.py`; prefer those over hardcoding. Integrity scanners use `ThreadPoolExecutor` with `--workers` (default 4).

Progress reporting goes through `utils._make_pbar`, which dispatches between three implementations: `vir_tui.progress_box` (while a vir_tui session owns the terminal, read via `vir_tui.session_screen()`), `tqdm` (when installed and not quiet), and `_FallbackProgress` (plain stdout). New modes should call `_make_pbar`, not `tqdm` directly.

`AUDIO_EXTENSIONS` in `config.py` is the canonical set of supported formats; extend it there, not inline. `COVER_NAMES` is matched case-insensitively (see `utils._has_cover_file`); add new variants there.

> **Important:** The generic UI formatting and Curses menu primitives live in the `vir-tui` shared repository. lattice-music depends on it for its interactive mode.

## Companion scripts (scripts/)

Nine standalone helpers. Six are launchers: `cleaner.py`, `apestrip.py`, `replaygain.py`, `retag.py`, `genre_tidy.py`, `genre_foldermap.py` re-export the package implementations via PEP 562 `__getattr__` (never copy code into them). The other three (`rerate.py`, `slipcover.py`, `flac2opus.py`) remain standalone until their own fold lands, because each mutates state in a way the package contract (spec.md §5) reserved for the write modes. **Don't fold any of the remaining scripts into the `lattice` package without asking.**

Behavior documentation lives in README's Companion scripts section. This section carries only the decisions and divergences:

- The package write modes invert the script defaults on purpose: `run_clean`/`run_apestrip`/`run_replaygain`/`run_retag`/`run_genre_tidy_apply` (and therefore their `lattice --*` flags and the TUI) dry-run unless `--apply`, while the launchers keep apply-by-default so aliases and cron don't change.
- `--retag` is the package's one genre-write path: `retag_directory(target_dir, genres, *, dry_run, log, errors)` is the loop `genre_tidy` drives in-process (by import, never by script path or subprocess), and `apply_genres` takes an `errors` list so in-process callers collect per-file failures where the standalone path prints them to stderr. clean's Pass 4 never writes genre and shares only the MP3 save convention with retag (ID3v2.3 plus a refreshed ID3v1).
- `genre_tidy`'s private `_QUOTE_DASH_FOLD` key table stays deliberately narrower than `lattice.norm.normalize_name` (which strips apostrophes from keys): switching would re-key saved maps and re-append quoted-name artists as new; pinned by FoldTableDivergenceTests.
- `--genreMap`'s `--allow-new-genre` stays opt-in in both entry points (the conservative default; every recorded launcher run passes it explicitly).
- apestrip's default is the corrected pure strip (nothing migrates); `--keep-metadata` opts into migration, and even then genre is never migrated and ratings are never written (APE↔POPM scales differ; see `rerate.py`).
- `rerate.py` stays MP3/POPM-only with its fixed REMAP (`127→64`, `254→196`, the bytes both players read identically); measured on the real library, idempotent, and it leaves foobar's canonical bytes and MusicBee's alone.
- Pattern for future destructive helpers: positional `directory` arg matching `retag.py`, `--dry-run` short-circuiting all destructive ops through a single guard layer, append-only timestamped log with `--log` override, idempotent on re-run, narrow scope. Document it in README under its own section, add a dated no-bump patchnotes entry, and add a constraint bullet here.

**Relationship to `--duplicates`.** The package's `--duplicates` mode is detection-only (a text report). `cleaner.py` is the destructive companion for the subset of duplicates that are quote-/dash-/case-variant folder-name artifacts. It merges by folder name only, so the merge is auditable from the log alone; the opt-in `--normalize-tags` pass reads tags but only to rewrite them under an already-chosen survivor, never to decide a merge. Run `--duplicates` first, then `cleaner.py --dry-run`, then apply.

## Conventions for this repo

- lattice-music is read-only by default: it reads tags, decodes audio, and writes reports/playlists/extracted art/queryable exports (`--exportDb`'s SQLite snapshot of the GENRE (primary) -> ARTIST -> ALBUM -> SONG hierarchy: rebuilt wholesale each run into a temp file + atomic swap, `--output` required, never read back by lattice, so the filesystem stays the source of truth; spec.md §4/§5 carry the amended wording). It writes metadata back to audio files only through the explicit write modes, `--clean`, `--apestrip`, `--lyrics`, `--replayGain`, `--retag`, `--stripRatings` and `--genreTidy-apply` (opt-in via `--apply`, logged, dry-run by default; `--genreMap` is the one folder-moving mode: mv-only on one filesystem, manifest TSV + `--revert`, dry-run by default; `--lyrics` writes `.lrc` sidecars beside audio and is the one mode allowed to touch the network, for read-only LRCLIB lookups; `--replayGain` shells out to rsgain and refuses with exit 2 when it is missing; `--retag` is dir-scoped and refuses `--root`; `--stripRatings` deletes rating tags only, nonzero values only, via the tags.py rating-source helpers). Every other mode should respect that boundary; any new write surface needs its own contract amendment first.
- **Don't thread tag reads.** `get_all_tags` is GIL-bound (mutagen decodes in Python), so a pool is 1.4-1.5x *slower* than serial on local storage; measured with hyperfine on the 9.6k-file library, 2026-08-09. `_scan_album_dirs` and `generate_playlist` are deliberately serial, and `read_tags_concurrent`/`map_concurrent` default to one worker via `config.DEFAULT_TAG_WORKERS` (opt back in with `tag_workers`/`LATTICE_TAG_WORKERS` for network or spinning-disk volumes). If you benchmark this again, measure user CPU with a warmup: wall clock on a warm page cache once made the slower version look 2x faster. The integrity modes' `--workers` pool is unrelated and genuinely helps (flac/ffmpeg subprocesses release the GIL).
- **Integrity progress files are transient caches, not an index.** The FLAC and MP3 scans persist per-file verdicts to `<output>.progress.json` write-through (beside a report FILE; a stdout report anchors no state), keep it only while the last scan is unfinished, and delete it on completion; `--resume` (FLAC/MP3 only) reuses recorded verdicts when the verification tool is unchanged, and refuses without --output (exit 2). Never grow this into a scan database; the filesystem stays the source of truth.
- One file per mode group under `modes/`. Adding a brand-new operation usually means a new function in an existing mode file, not a new file.
- Keep `pyproject.toml`, `spec.md` §1 header, and `config.VERSION` in lockstep on a release. `patchnotes.md` and `roadmap.md` are hand-curated; update them when the user asks.
- Default to no comments; `tags.py` has a few because the format quirks aren't obvious from the code, and that's the bar.
- The standard layout assumption is `ARTIST/ALBUM/Track.ext`, but `--layout` (default `{artist}/{album}`) lets callers override it via `utils.parse_layout`. Don't hardcode `os.sep`-counting logic; use `parse_layout`.
- **`--ingest` sequences the ritual, it never re-implements** (B4): modes/ingest.py calls run_stripratings (staging-scoped: over root/<staging> only; the ritual never rating-strips the filed library, whose rating tags may be the owner's own hand ratings) -> run_genremap -> run_apestrip -> run_clean(all passes) -> run_health in process; per-stage TTY confirm (auto-proceed on non-TTY, the house convention; the TUI's ask_yn is the gate); one summary file (<root>/ingest_summary.txt, --output overrides; '-' streams it to stdout and the digest/diff sidecars stay beside the root) points into the per-stage logs; --baseline SNAPSHOT adds a diff report. A declined stage is recorded and skipped, never fatal. Not a new write verb: no §5 change beyond A4's.
- **`--health` is the one-walk digest** (B3): `run_health` in modes/audit.py reads each file's TagBundle once and feeds the shared lens code (the derivation principle: `_tag_findings` is auditTags' classifier, `_rg_bucket` the RG buckets, `_album_health` the scorer, `classify_stray` the stray buckets, `check_playlist` the playlist check; the exact-album-dupe count keys through the exact lens's `_norm_key` fold, so casing/quote variants of one album count once), so digest and audits cannot drift. Always exits 0; `--json` supported (no --fail-on-findings: it informs, the audits gate). TUI entry (3, 11).
- **`--json` / `--output -` / `--fail-on-findings`** (B2): the machine shapes. `utils.json_report` is the uniform audit/stats envelope ({mode, root, findings, payload}); `utils.json_summary` is the write-run summary ({mode, root, dry_run, counts}); every report site goes through `utils.resolve_output`, which passes `-` through to `utils.open_report` (stdout). Under the v6.5.0 report discipline, `resolve_output(output)` takes no default: omitting `--output` is stdout for EVERY report mode (spec §4 amended), a stdout integrity run persists no progress state, and `--resume` without `--output` refuses with exit 2. Support is explicit: `_JSON_MODES` (stats, the six tag-reading audits, and the write modes except lyrics and genreTidy-build, plus health and ingest) and `_FAIL_MODES` (the six audits) in cli.py refuse unlisted modes with exit 2. Exit discipline: findings gate exit 1 only under `--fail-on-findings` (default 0), refusals stay 2, interrupt 130.
- **`--where` is the global selector** (B1): `compile_where` in `lattice.modes.playlists` compiles the playlist rule grammar into a TagBundle predicate; `library._scan_album_dirs(roots, layout, pbar, where=...)` is the choke point for the exports and the genretidy/foldermap scans; stats and the tag-reading audits filter their own loops. Write targeting is album-granular by pinned rule (any matching track selects the whole album). The supported-mode set is `_WHERE_MODES` in cli.py: a mode not listed refuses `--where` with exit 2, so new modes opt in explicitly. The TUI does not prompt for `--where` (the CLI passes `where=None` by default, which the kwargs-parity binder treats as identical to the TUI's omission).
- **Tag deduplication.** ffmpeg remuxing or merging ID3v1 and ID3v2 tags often results in duplicate values joined by `/` or `, ` (e.g., `The Game / The Game`). clean's `--normalize-tags` handles this with `tag_dedupe`, which reduces exact case-insensitive matches and substrings down to their unique canonical representations.
- **Historical tag gap (decided 2026-11-24, leave as-is):** the 42 pre-v5.0.0 versions carry patchnotes entries but no git tags, and v2.0.0 is a lightweight tag. The per-release tag discipline is enforced from v5.0.0 forward, and every tag since is healthy. Backfilling would flood the releases page with backdated releases for no consumer; audits should not re-flag this.

## Release flow

Commit and push verified work (the standing push grant in the global file; force-pushes still need approval), wait for CI to go green, then tag: annotated `vX.Y.Z` at the release commit, message = that release's patchnotes entry verbatim (`--cleanup=verbatim`; the full tag procedure lives in `~/.zcode/AGENTS.md`). Version carriers, in lockstep per the conventions above: `src/lattice/config.py` VERSION, `pyproject.toml`, and the spec.md §1 header. If the change touched the help surface, run `just help-doc` so `docs/help.md` matches the release (the test pins it).
