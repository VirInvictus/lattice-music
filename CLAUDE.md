# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

lattice-music is a CLI/TUI toolkit for music libraries that treats the filesystem as the source of truth. It reads tags through `mutagen`, walks the tree on every invocation (no index/database), and writes plain `.txt` reports. Since 5.0.0 it also carries the two opt-in write modes promoted from the companion scripts (`--clean`, `--apestrip`: dry-run by default, `--apply` to write, always logged). Python 3.14+, packaged with Hatch (`pyproject.toml`). Runtime deps: `mutagen`, `tqdm`, `vir-tui` (TUI primitives; PyPI floor `>=2.2.0`). The current version is kept in `src/lattice/config.py` and mirrored in `pyproject.toml` (must stay in sync).

The system-wide conventions file at `~/.zcode/AGENTS.md` covers global rules (zsh aliases, package managers, dotfiles repo). This file overrides it for work scoped to lattice-music.

## Common commands

```bash
# Run from a checkout (without installing)
python -m lattice [flags]              # entrypoint: src/lattice/__main__.py

# Install editable into the active venv (uv-friendly)
pip install -e .

# Install as a user-global CLI
pipx install .                         # exposes `lattice`

# Standalone binary (PyInstaller, declared in pyproject.toml)
hatch run build-bin                    # → dist/lattice

# Launch interactive TUI (no args)
lattice

# Most-used modes
lattice --library --output library.txt --genres
lattice --testFLAC --workers 4
lattice --extractArt --dry-run
lattice --stats

# Write modes (dry-run by default; --apply writes, always logged)
lattice --clean ~/Music --apply
lattice --apestrip ~/Music --apply --keep-metadata
```

Tests live in top-level `tests/` (stdlib `unittest`, no third-party deps); run them from the repo root with `python -m unittest discover` (501 tests as of v5.0.0). They cover the pure helpers (rating/key normalization, duration clustering, JPEG/PNG header parsing, filename cleanup, track-number parsing, decode classification) and the mode functions end to end against a committed fixture library (`tests/fixtures/library/`, regenerated by `tests/fixtures/build.py` with ffmpeg + mutagen). The `scripts/` companions are tested too (`test_retag.py`, `test_cleaner.py`, `test_genre_tidy.py`, `test_rerate.py`, `test_genre_foldermap.py`, `test_replaygain.py`, `test_apestrip.py`): pure helpers directly, mutating paths against tempfile trees / fixture copies. `test_cleaner.py` and `test_apestrip.py` exercise the package modules behind those two scripts (`lattice.norm`, `lattice.modes.clean`, `lattice.modes.apestrip`); `test_write_modes.py` pins the CLI/TUI wiring of the write modes. Integrity modes that shell out to flac/ffmpeg are not exercised; their `classify_decode` brain is unit-tested instead. When changing a covered helper or mode, update its test in the same pass.

System tools used by integrity modes: `flac` (preferred for `--testFLAC`) and `ffmpeg` (everything else, plus FLAC fallback). Both should already be on Fedora via `dnf`.

## Architecture

Layer-based package under `src/lattice/`:

```
cli.py     argparse + dispatch: every mode flag maps to one function call
tui.py     curses full-screen menu shown when invoked with no args
tags.py    get_all_tags() → TagBundle, single MutagenFile() open per file
norm.py    pure name/tag normalization rules (the fold tables, normalize_name,
           canonical_render, tag_fold, tag_dedupe, canon_track_artist); zero I/O
config.py  VERSION, DEFAULT_*_OUTPUT names, AUDIO_EXTENSIONS, COVER_NAMES,
           the tag-read worker count (DEFAULT_TAG_WORKERS/get_tag_workers),
           and persistent library root in ~/.config/lattice/config.json
utils.py   filesystem walk, progress bar factory (_make_pbar), subprocess
           helper, layout parser, terminal reset
modes/     one file per mode group: library, integrity, artwork, audit,
           stats, playlists, clean (the --clean write mode: Run virtual
           filesystem + the four consolidation/normalization passes),
           apestrip (the --apestrip write mode). Each exports run_* /
           write_* functions.
```

Both `cli.py` and `tui.py` call into `modes/*` directly. The TUI is not a wrapper around the CLI parser; it builds the same kwargs and invokes the same mode functions. Keep them in sync when adding a flag: argparse entry in `cli.py`, dispatch branch in `cli.py:main`, and a corresponding TUI menu entry in `tui.py`.

`tags.py` is the only place that knows about per-format tag layouts (ID3 frames, Vorbis comments, MP4 atoms, ASF). All other code consumes a `TagBundle`. Ratings are normalized to a 0–5 float in `utils.normalize_rating`; format-specific rating sources (POPM, TXXX, Vorbis `RATING/SCORE/STARS`, MP4 `*rate*`) are decoded inside `get_all_tags`.

Mode functions accept `root`, `output`, `quiet`, and (where relevant) `workers`, `verbose`, `dry_run`, `layout`. Output paths default to constants in `config.py`; prefer those over hardcoding. Integrity scanners use `ThreadPoolExecutor` with `--workers` (default 4).

Progress reporting goes through `utils._make_pbar`, which dispatches between three implementations: `_TUIPbar` (when `utils.IN_TUI` is set by the TUI before invoking a mode), `tqdm` (when installed and not quiet), and `_FallbackProgress` (plain stdout). New modes should call `_make_pbar`, not `tqdm` directly.

`AUDIO_EXTENSIONS` in `config.py` is the canonical set of supported formats; extend it there, not inline. `COVER_NAMES` is matched case-insensitively (see `utils._has_cover_file`); add new variants there.

## Companion scripts

Nine standalone helpers live in `scripts/`. Two of them, `cleaner.py` and `apestrip.py`, were folded into the package in 5.0.0 (Brandon commissioned the fold; the spec.md §5 amendment is that asking) and are now argparse-preserving launchers that re-export the package implementation via `lattice.modes.clean` / `lattice.modes.apestrip` (PEP 562 `__getattr__`; never copy code into them). The other seven remain **not** part of the `lattice` package and not exposed through the CLI, because each one mutates state in a way the package contract (spec.md §5) reserves for the two write modes. Don't fold any of the remaining seven into the `lattice` package without asking.

The two write modes invert the script default on purpose: `run_clean`/`run_apestrip` (and therefore `lattice --clean` / `lattice --apestrip` and the TUI) dry-run unless `--apply` is passed, while the scripts keep apply-by-default so aliases and cron don't change. The `--clean` tag pass writes ID3v2.3 plus a refreshed ID3v1 on MP3 (matching `retag.py`) and native fields elsewhere.

- **`retag.py`**: universal genre rewriter. Writes tags via `mutagen`, abstracting per-container differences (ID3, Vorbis, Apple atoms). Designed to consume the `--all-wings --paths` output one album at a time. It deletes any APEv2 tag as a side effect of rewriting the genre (the "deadbeef won't update" trap), but only the genre; `apestrip.py` is the general, lossless APEv2 stripper.
- **`rerate.py`**: MP3 rating reconciler. DeaDBeeF and foobar2000 store POPM ratings on different 0–255 byte scales, so a DeaDBeeF 2★ (byte 127) reads as 3★ in foobar and a 4★ (byte 254) reads as 5★. `rerate.py` rewrites the offending bytes to foobar's equivalents that **both** players read identically (`127→64`, `254→196`; map in `REMAP`), fixing foobar without changing DeaDBeeF's display (verified: byte 196 reads 4★ in both). MP3/POPM-only; leaves foobar's canonical bytes, MusicBee's `186/242`, unrated, and non-MP3 files alone (Vorbis/Opus ratings already agree). `--dry-run`, append-only log (`<directory>/rerate.log`), idempotent. Tested by `tests/test_rerate.py`.
- **`genre_tidy.py`**: two-phase artist→genre authority + reconciler, layered on top of `retag.py`. `build` scans through lattice (read-only, importing `library._scan_album_dirs`) and writes an editable tab-separated `genre_map.tsv`: one `Artist<TAB>Genre<TAB>Genre2<TAB>...` line per artist listing **every** genre that artist currently uses (most-common first = canonical), with `#` comments giving per-genre counts for multi-genre artists. Every listed genre is allowed, so a fresh map makes `apply` a no-op; you tidy by **removing** a stray genre from a line, which makes `apply` re-scan and call `retag.py` on that artist's albums tagged with the removed genre, collapsing them to the first (canonical) genre. Reorder to retarget; leave only the artist (no genres) to skip. Keys on the normalized artist **tag**, not folder name (and `TagBundle.artist` prefers the album-artist). Compilation album-artists (`EXCLUDED_ARTISTS` = various artists/various/va) are flagged `EXCLUDED` as a comment, never get an enforceable row, and `apply` hard-skips them: a comp has no single canonical genre. `--dry-run`, append-only log (`<directory>/genre_tidy.log`), idempotent; re-running `build` preserves edits and only appends new artists (a fresh format needs the old map deleted first). Aimed at messy libraries; a cleanly tagged one reports everything compliant. The repo ships Brandon's real ~877-artist map as `artist_genre_defaults.tsv` (his maintained authority; pass it with `--map`, grow it by re-running `build`). The tool's own default map path is still `<library>/genre_map.tsv`. Tested by `tests/test_genre_tidy.py`.
- **`cleaner.py`** (launcher; the implementation is `lattice.norm` + `lattice.modes.clean`, exposed as `lattice --clean`): fragmented-album folder consolidator. When import metadata varies across sources (curly vs straight apostrophe in album titles, en-dash vs hyphen in artist names, casing variants), the same album lands in two sibling folders with no track overlap. The tool walks the library, finds folders whose names normalize to the same key (curly→straight quotes, dash variants→ASCII hyphen, NFKC, lowercase, strip), picks the larger as canonical, and merges the rest in via `shutil.move`. Audio collisions where sizes differ are kept under a `.from-fragment` suffix, never auto-deleted; cover-image collisions keep the higher-resolution file (artwork's `_get_image_size`); other non-audio collisions drop the source. After merging, the survivor is renamed to its normalized form via `canonical_render` (a narrow fold: broken hyphens U+2010/11/12/15, curly quotes/apostrophes, and ellipsis → ASCII; **en/em dashes and primes preserved**, unlike `normalize_name`'s aggressive matching fold). **`--normalize-names` (opt-in) is a third pass that renames non-duplicate folders at every depth (v1.3.0 made it fully recursive; was 2 levels) the same way; `--normalize-filenames` (v1.3.0) does the same for audio track files (extension kept verbatim), a separate flag because renaming files is a distinct change.** **`--normalize-tags` (opt-in) is a fourth, library-wide pass (v1.3.0; was MP3-only + merged-folders-only in v1.2.0).** Title and album tags get a pure typographic fold (`tag_fold`: CP1252 mojibake, curly quotes, broken hyphens → clean; **en/em dashes, ellipsis, primes preserved** like `canonical_render`, so `85–92` keeps its en dash and a mojibake dash is repaired to a real dash, not a hyphen); the words never change, so the folder is never an authority for title/album. Artist/albumartist fold the same way everywhere, except under a merged or renamed artist folder where they are restamped to the surviving folder name (authority) with a trailing `feat.` guest preserved. All formats (`normalize_file_tags` dispatches ID3/Vorbis/MP4/ASF, mirroring `retag.py`; MP3 stays ID3v2.3 + refreshed v1); only changed fields written, clean files are no-ops (idempotent), unsupported audio (`.wav` etc.) reported and skipped. The authority *depth* is read from `--layout` (default `{artist}/{album}`; pass `{genre}/{artist}/{album}` for a genre-foldered library). Dry-run faithfully predicts the real run (virtual removals AND creations; the tag pass resolves a not-yet-moved source file to its survivor authority so the preview matches apply). Inside the package the dry-run is the default; this script keeps apply-by-default. Per-file logging to `<directory>/cleanup.log` by default. Note: the *merge* passes (1-2) are still depth-fixed two levels deep, so on a `Genre/Artist/Album` library an artist-variant split is caught as an album-level group within each genre; album-folder merges there need the tool pointed at a genre folder.
- **`genre_foldermap.py`**: restructures a flat `Artist/Album` library into `Genre/Artist/Album`, moving each album folder under its dominant genre (read through lattice's scanner). `mv`-only on one filesystem, so audio bytes and embedded ratings are never rewritten. Dry-run by default; `--apply` performs it and writes a manifest TSV that `--revert` replays in reverse. `--only-genre` for a staged rollout; loose singles wrap into a `Singles/` folder; artist-level sidecars (e.g. `Artist/cover.jpg`) follow the artist to its genre. Pairs with the `{genre}/{artist}/{album}` layout config key. **`classify` is depth-aware (v1.2.0): depth-2 `Artist/Album` is a stray to file, depth-3 `Genre/Artist/Album` is already organized (in-place skip; folder/tag genre mismatch → `NOTE`, never auto-refiled), depth ≥4 is flagged `TOO DEEP` and skipped — the guard against pointing the tool at the parent of an organized library. Placement is gated by the genre vocabulary derived live from existing depth-3 folders: a stray whose tag genre isn't already in use is flagged `UNKNOWN GENRE`, not given a new top-level folder, unless `--allow-new-genre`. An empty vocabulary (flat library) disables the gate, preserving the first-time conversion. No persisted genre cache: derived each run, in keeping with the filesystem-as-truth design.** **Staging inbox (v1.3.0): a leading `--staging` folder component (default `Unfiltered`, `--staging ""` to disable) is stripped before `classify`, so a tagger's `Unfiltered/Artist/Album` dump files into the real taxonomy like a flat stray instead of reading as a genre named "Unfiltered"; the vocabulary gate still applies, the per-artist source dirs prune, and the inbox folder itself is left in place.** Tested by `tests/test_genre_foldermap.py`.
- **`apestrip.py`** (launcher; the implementation is `lattice.modes.apestrip`, exposed as `lattice --apestrip`): APEv2 stripper for MP3s. Some MP3s (torrent rips) carry a hidden APEv2 tag alongside ID3; players that read APEv2 on MP3 (foobar2000, DeaDBeeF) merge its values over ID3, so a stray APE genre like `Trash Metal` reappears as `Trash Metal, Metal` and ordinary tag editors never touch it. **By default (v1.1.0) it is a pure strip: the APEv2 block is deleted and ID3 is left byte for byte; nothing is migrated.** This is the corrected default; migrating APE values into ID3 unprompted is how a bad APE genre gets baked into the real tags. **`--keep-metadata`** opts into the old behavior: before deleting the APEv2 tag, **every APE field whose value isn't already in ID3 is migrated into the right ID3 frame** (core text → native frames, `Comment`→COMM, `Cover Art (Front)`→APIC, `Unsynced lyrics`→USLT, sort orders → TSO*, everything else → `TXXX:<key>` passthrough). Two exceptions hold even under `--keep-metadata`: **genre is never migrated** (ID3 authoritative; the APE genre is the value being removed; no ID3 genre → reported, not invented) and **rating is never written** (APE↔POPM scales differ, so auto-conversion would corrupt stars; see `rerate.py`. APE ratings are reported). Genre and rating are reported in both modes. Recursive over the directory (one album or the whole library), MP3-only, worklist confirmation before a real write (`--yes` to bypass, auto-bypass when non-TTY; the package mode dry-runs by default instead), append-only log (`<directory>/apestrip.log`), idempotent. A plain strip rewrites no ID3; migrations (under `--keep-metadata`) saved as ID3v2.3 + refreshed ID3v1, matching `retag.py`. **Malformed APE tags mutagen can't parse** (e.g. footer with the IS_HEADER bit set, junk before a trailing ID3v1) are **reported by default** and only fixed with `--repair-malformed`, which parses the tag from raw bytes, migrates sole-source fields (only with `--keep-metadata`), then excises the block via direct byte surgery gated on a structural proof (footer at `header+size`), writing to a temp file and atomically swapping after verifying it still decodes with no APE signature left. Audio frames + trailing ID3v1 preserved byte for byte. Tested by `tests/test_apestrip.py`.
- **`replaygain.py`**: ReplayGain 2.0 writer — the mutating companion to the read-only `--auditReplayGain` package mode. Wraps `rsgain easy` (libebur128, -18 LUFS / 89 dB reference, the foobar2000 "Scan selection as album" behavior) to compute and write per-track and per-album gain/peak tags. **Album = one folder, rescanned as a whole** so album gain is correct; `--skip-tagged` skips a fully-tagged album *as a unit* (half-skipping would compute album gain over a subset and corrupt it). `--dry-run` lists albums + current coverage without invoking rsgain; a real run prints the worklist and asks for confirmation before writing (`--yes` to skip; auto-skipped when stdin is not a TTY). After each album the written tags are read back and logged. `--target-lufs N` switches from `rsgain easy` (the default 89 dB / -18 LUFS standard) to `rsgain custom -l N` for a louder/quieter target (e.g. -14 ≈ 93 dB); custom mode writes standard `replaygain_*` tags for every format including Opus (R128 is fixed at -23 LUFS so it can't carry a custom target), range -30..-5. Imports `lattice` for the format-aware `read_replaygain`; **requires `rsgain` on PATH** (not bundled; `sudo dnf install rsgain` on Fedora). `--threads` passes through to `rsgain easy -m` (no-op with `--target-lufs`, where rsgain's `-m` means max-peak). Append-only log (`<directory>/replaygain.log`), idempotent. Tested by `tests/test_replaygain.py` (helpers direct, rsgain mocked). Same detection/mutation split as `--duplicates` ↔ `cleaner.py`.
- **`slipcover.py`**: Cover art embedder. The mutating companion to `--missingArt`. Walks a directory recursively; when it finds an audio folder lacking embedded art but possessing a folder image (`cover.jpg`, etc. as defined in `COVER_NAMES`), it embeds that image into the audio files. Idempotent: files that already carry embedded art are skipped. Format support mirrors `extractArt` (MP3, FLAC, Opus/OGG, M4A). `--dry-run` to preview, asks for confirmation before writing (`--yes` to skip). Append-only log (`<directory>/slipcover.log`).
- **`flac2opus.py`**: FLAC-to-Opus converter. Recursively finds FLAC files, encodes them to Opus at 128k via `ffmpeg`, verifies output quality (duration match), copies the tags via Mutagen, and only then deletes the FLAC originals; a failed verify removes nothing.

**Relationship to `--duplicates`.** The package's `--duplicates` mode is **detection-only**: it reports same-`artist+album` appearances across multiple directories or formats and writes a text report. `cleaner.py` is the **destructive companion** for the specific subset of duplicates that are quote-/dash-/case-variant artifacts of the same folder name. `cleaner.py` does not key off tags for *merging*; it matches folder names only, so the merge is auditable from the log alone (the opt-in `--normalize-tags` pass reads tags, but only to rewrite them under an already-chosen survivor folder, never to decide a merge). The two are complementary: run `--duplicates` first to see what's going on, then run `cleaner.py --dry-run` to preview the safe subset, then apply.

**Pattern for future destructive helpers.** If you add another mutating helper in `scripts/`, follow the same shape: positional `directory` arg matching `retag.py`, `--dry-run` short-circuiting all destructive ops through a single guard layer, append-only timestamped log to a sensible default path with `--log` override, idempotent on re-run, narrow scope. Document it in README.md under its own "Companion Script: `<name>.py`" section, add a dated entry in `patchnotes.md` (no version bump, since the package didn't change), and add a bullet here.

> **Important:** The generic UI formatting and Curses menu primitives have been extracted to the `vir-tui` shared repository. lattice-music relies on this external dependency for its interactive mode.

## Conventions for this repo

- lattice-music is read-only by default: it reads tags, decodes audio, and writes reports/playlists/extracted art. It writes metadata back to audio files only through the two explicit write modes, `--clean` and `--apestrip` (opt-in via `--apply`, logged, dry-run by default; spec.md §5 carries the amended wording). Every other mode should respect that boundary; any new write surface needs its own contract amendment first.
- **Don't thread tag reads.** `get_all_tags` is GIL-bound (mutagen decodes in Python), so a pool is 1.4–1.5× *slower* than serial on local storage; measured with hyperfine on the 9.6k-file library, 2026-08-09. `_scan_album_dirs` and `generate_playlist` are deliberately serial, and `read_tags_concurrent`/`map_concurrent` default to one worker via `config.DEFAULT_TAG_WORKERS` (opt back in with `tag_workers`/`LATTICE_TAG_WORKERS` for network or spinning-disk volumes). If you benchmark this again, measure user CPU with a warmup: wall clock on a warm page cache once made the slower version look 2× faster. The integrity modes' `--workers` pool is unrelated and genuinely helps (flac/ffmpeg subprocesses release the GIL).
- One file per mode group under `modes/`. Adding a brand-new operation usually means a new function in an existing mode file, not a new file.
- Keep `pyproject.toml`, `spec.md` §1 header, and `config.VERSION` in lockstep on a release. `patchnotes.md` and `roadmap.md` are hand-curated; update them when the user asks.
- Default to no comments; `tags.py` has a few because the format quirks aren't obvious from the code, and that's the bar.
- The standard layout assumption is `ARTIST/ALBUM/Track.ext`, but `--layout` (default `{artist}/{album}`) lets callers override it via `utils.parse_layout`. Don't hardcode `os.sep`-counting logic; use `parse_layout`.

- **Tag deduplication.** ffmpeg remuxing or merging ID3v1 and ID3v2 tags often results in duplicate values joined by `/` or `, ` (e.g., `The Game / The Game`). `cleaner.py` handles this during `--normalize-tags` using `tag_dedupe`, which reduces exact case-insensitive matches and substrings down to their unique canonical representations.
